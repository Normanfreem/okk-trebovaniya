# Требования ОКК — правила и шаблоны

Свод всего, о чём договорились при разработке (02.10.2026). Читать перед любой работой с данными или приложением.

## Что это

- Офлайн-приложение (PWA) для полевых сотрудников ОКК: требования НТД, проекта, РД и писем проектировщика со ссылкой на PDF-источник (открывается на нужной странице).
- Сайт: https://normanfreem.github.io/okk-trebovaniya/ (репозиторий Normanfreem/okk-trebovaniya, GitHub Pages).
- Данные — только в зашифрованном `data.okk` (AES-256-GCM, PBKDF2-SHA256 200k, формат `OKK1`+salt16+iv12+шифртекст). Пароль знает только ответственный ОКК — **никогда не класть пароль, Excel и PDF в репозиторий** (он публичный). Документация с ограничением распространения.
- Обновление: раз в ~10 дней, меняет данные только ответственный. Приложение само проверяет `version.json`, скачивает `data.okk`, расшифровывает сохранённым паролем, показывает «Изменения».

## Файлы в `src/`

| файл | что |
|---|---|
| `app.src.html` | исходник приложения (библиотеки по CDN, `__DEMO_ZIP__` — демо) |
| `build_all.py` | сборка: `pwa/index.html` (всё встроено, офлайн) + поднимает версию кэша в `pwa/sw.js` |
| `encrypt.py` | `python3 encrypt.py <zip> <пароль> <папка> <ДД.ММ.ГГГГ>` → data.okk + version.json |
| `pack_tool.py` | проверка Excel, автозаполнение «Вид материала», zip, шифрование |
| `make_xlsx.py` | стили листов Excel (`style_sheet`, `REQ_HEAD`, `DOC_HEAD`) |
| `demo_old.zip` | демо-данные (выдуманные) |

Восстановление рабочей папки:
```
mkdir -p okk/pwa && cp src/* okk/ && cp index.html sw.js manifest.webmanifest pack.html icon-*.png okk/pwa/
cd okk && npm i jszip@3.10.1 pdfjs-dist@3.11.174 xlsx-js-style@1.2.0 && python3 build_all.py
# затем скопировать okk/pwa/index.html и okk/pwa/sw.js в корень репозитория, commit, push
```

## Формат пакета данных

Zip: `Требования_ОКК.xlsx` + папка `Документы/` с PDF. Листы Excel:

- **Инфо**: «Актуально на» = дата пакета.
- **Требования**: ID | Объект | Конструктив | Элемент | Блок | Материал / что проверяем | Вид материала | Требование | Документ | Стр. | Статус | Заменено на | Дата изменения | Примечание.
- **Документы**: Код | Тип (Проект, РД, Письмо, СП, ГОСТ, Памятка, Прочее) | Название | Дата | Файл PDF | Описание.
- **Как заполнять** — памятка.

Правила заполнения:
- **ID стабильные** (ЖБТ-001…), при удалении строк не перенумеровывать — иначе «Изменения» покажут ложные правки. Новые — следующим свободным номером.
- **Блок**: только `Материал` (входной контроль), `Устройство`, `Приёмка`.
- **Требование**: `Показатель - значение; Показатель - значение`. Таблица: `Заголовок, ед.:; строка - значение; строка - значение`. Слово-показатель пишется один раз (напр. «Прямолинейность, мм:; на 1 м - 7,5; на 2 м - 10,5»).
- **Несколько источников**: `Документ` = `код1; код2`, `Стр.` = `1; 2` в том же порядке.
- **Одна карточка из нескольких строк**: одинаковые Элемент + Блок + Материал → одна карточка, у каждой части своя ссылка на источник.
- **Замена письмом**: старой строке Статус «Заменено», «Заменено на» = новый ID; новая строка с датой изменения. Строки не удаляем.
- **Примечание**: справочные ссылки вида «Письмо…», «СП …», «ГОСТ…», «Применяется по письму…», «Класс —» в приложении скрываются; остальное показывается подписью.
- Пользователь присылает свой Excel со столбцом «Послание для Claude» (первый столбец — номер группы, не порядковый): ответы возвращать в его же файле в столбце «Решение Claude».
- Сомнительные места — в Примечание («понято как…», «проверить…») и сообщить пользователю.

### Договорённости по содержанию (решения пользователя)

- Класс бетона всегда как `Класс по прочности - B20` (не «Бетон - мелкозернистый B20»; слово «мелкозернистый» не пишем).
- Сборные изделия (звенья, стенки откосные, фундаментные блоки): `Отпускная прочность - не менее 100 % проектной`.
- Поверхность: классы А4 и А6 — по одной карточке на класс (Применяется / Раковины-сколы / Прямолинейность в одной карточке).
- Дефекты: две карточки «Дефекты — не допускаются» (включая брак) и «Дефекты — допускаются с ремонтом».
- Отклонения размеров и толщина защитного слоя — в блоке «Материал» изделия.
- Толщина щебёночной подготовки — внутри строки щебня (`…; Толщина - 20 см`).
- Конструктивы: «Железобетонные трубы» (ID ЖБТ-…) и разделы земляного полотна (ID ЗП-…). **Каждая группа из Excel пользователя (первый столбец — номер группы) = отдельный конструктив на главном экране**, не элемент внутри общего. Порядок — по номеру группы. Группы не объединять, даже если тема похожа. Внутри группы элементы — только если в группе явно разные участки (напр. «Замена слабого грунта»: два участка); иначе один элемент с именем конструктива (приложение откроет сразу карточки).
- «Дренирующий» грунт/заполнитель = коэффициент фильтрации не менее 0,5 м/сут — писать это значение строкой «Коэффициент фильтрации … - не менее 0,5 м/сут» (решение пользователя).
- Степень неоднородности — как в письмах: «более 3» (не «не менее 3»). «Лунки» — ГОСТ Р 70260-2022, Проктор — ГОСТ Р 70456-2022.
- Требование, относящееся только к части материалов (напр. только к песку) — пишется в карточку именно этого материала; условие применения — строкой «Применяется - …» или заголовком таблицы.
- «Тело земляного полотна»: два блока-элемента — «Крупнообломочный грунт» и «Песок гравелистый, крупный, средней крупности» (не «Другие грунты»); в каждом свой материал и все требования приёмки, которые к нему относятся (общие требования повторяются в обоих блоках, у копии свой ID). Деление на «Материал / Приёмка» внутри не показывать. Каждый блок — ОДНА карточка со всеми данными (подзаголовки внутри), не несколько карточек.
- Ссылка на документ стоит РЯДОМ с тем требованием (частью карточки), к которому относится, а не общим списком на всю карточку. Для всех конструктивов.
- Входной контроль партии геосинтетики — отдельная карточка «Входной контроль партии» первой в элементе.
- Письмо без PDF: на листе «Документы» файл пустой, в «Описании» — суть письма (приложение покажет её вместо PDF).

### Вид материала (вкладка «Материалы»)

Порядок и точные названия (новое название = новая группа; при добавлении — внести в `CAT_ORDER` в app.src.html и pack_tool.py):

Щебень · Песок и грунт · **Монолитный бетон** · **Сборные ЖБ и бетонные изделия** · Арматура · Растворы · Гидроизоляция · Материалы для швов · Геосинтетика · Камень · Металлоконструкции и окраска

Монолитный бетон и сборные/бетонные изделия — **раздельно** (решение пользователя). Для строк «Приёмка», отклонений и защитного слоя — пусто. Пустые значения `pack_tool.py` заполняет по правилам `cat_for()`.

## Вид приложения (шаблоны, утверждены пользователем)

Цвета: тёмно-синий `#1d3a5c` (шапка), синий `#154677`, голубой фон чипов `#e3eef9`, фон `#eef1f0`, линии `#d7dedc`. Шрифты IBM Plex Sans / Plex Mono.

**Конструктив / элемент (карточки)**
- Компьютер (≥1000 px): боковое меню, сетка карточек в 3 колонки; при 4+ карточках с чётным числом, не кратным 3 — 2 колонки по центру. Карточки ряда одной высоты, синие чипы-источники выровнены на одном уровне по ряду (`alignChips`). PDF открывается в боковой панели.
- Телефон: одна колонка, нижнее меню, PDF на весь экран, при возврате из документа — на то же место прокрутки.
- Заголовки разделов (Материал / Устройство / Приёмка) показываются, только если у элемента есть «Приёмка».
- Чип источника: только шифр документа, страница — «стр. N».

**Материалы**
- Список видов материала → страница вида: **широкая таблица, одна строка = одно место применения (конструктив/элемент)**, каждый параметр — отдельная колонка, последняя — «Документ» (чипы со стр.). Нет параметра — «—».
- Строки других блоков того же элемента (напр. толщина) подмешиваются колонками в строку материала.
- Если колонок > 7 (разные материалы, напр. гидроизоляция, швы) — отдельная таблица на каждый материал.
- Клик по месту применения → карточка элемента.
- Телефон: каждая строка — блок «параметр — значение», пустые скрыты.

**Выгрузка Excel (кнопка «Скачать Excel» на странице вида материала)**
- Файл `<Вид>_<дата>.xlsx`, один вид = один файл; несколько таблиц → лист на каждый материал.
- Оформление: тёмно-синяя шапка (название 16 pt жирн. белым + строка «Объект · Конструктив · Данные актуальны на»), заголовки колонок белым жирным на `#154677`, тонкие рамки `#C9D3D8`, зебра `#F4F7F8`, значения по центру, элемент жирным, шифр документа синим, «—» серым, без сетки, альбомная А4 «вписать по ширине», подпись «Выгружено из приложения… дата время».
- Колонки: № | (Конструктив — если их несколько) | Элемент | Материал | параметры… | Документ | Стр. | (Примечание — если есть).
- Библиотека xlsx-js-style (стили) + JSZip для настроек печати.

## Порядок работы при новых данных

1. Взять у пользователя актуальный `Требования_ОКК.xlsx` и папку `Документы` (или исходники: его Excel/PDF/скриншоты).
2. Перенести требования по правилам выше (стабильные ID, синтаксис, вид материала, объединения).
3. PDF: повернуть/обрезать до нужных листов, выписки из НТД — только нужные страницы.
4. `python3 pack_tool.py <папка> <ДД.ММ.ГГГГ> --pwd <пароль> --out out` → исправить ошибки.
5. Проверить в приложении локально (playwright, компьютер 1680 px и телефон 390 px), без ошибок JS.
6. Выложить `data.okk` + `version.json` в репозиторий (или пользователь сам через `pack.html`). Отдать пользователю обновлённый Excel.
7. Сообщить о сомнительных местах.
